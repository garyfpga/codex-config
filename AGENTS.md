# Xmake / C++ / CUDA
## C++ build artifacts
- `compile_commands.json` is auto-generated by the xmake VS Code extension - commit it.
## Native/CUDA build discipline
- After editing any native source or header that can affect compiled extensions (`*.c`, `*.cc`, `*.cpp`, `*.h`, `*.hpp`, `*.cu`, `*.cuh`), run `xmake b`.
- Do this before running Python notebooks/scripts/tests that import pybind11/CUDA extensions, and before claiming the native change is verified.
- If a requested `xmake b target_a target_b` command fails because the installed xmake accepts only one target argument, preserve the intended coverage by running each target build separately (`xmake b target_a`, then `xmake b target_b`) and then run the planned test command. Report the command-syntax mismatch explicitly.
## Xmake target defaults
- When adding C++/CUDA targets in `xmake.lua`, prefer release-with-debug mode and `-O3` optimization:
  ```lua
  add_rules("mode.debug", "mode.release", "mode.releasedbg")
  set_defaultmode("releasedbg")
  set_optimize("fastest")
  ```
- xmake's `fastest` maps to `-O3` for GCC/Clang/NVCC. Do not use `aggressive`/`-Ofast` as the default unless explicitly requested for a specific target.
